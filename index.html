What this is

A house style, and a small library, for web pages that do a job: control hardware, run experiments, take an operator through a procedure. Not for marketing.

It builds on plain-site, and its manifesto applies in full: plain HTML, the browser's own look, native controls, emoji next to words, colour only where it means something. plain-panel adds two things:

  • Signals. One store holds all the state. HTML attributes hold paths into it. The page always shows the ground truth: what is pending, what failed, how old the data is.
  • One exception: functional CSS. A few lines, from a short allowlist, where a tool needs a layout that HTML cannot give, like a stop button that never scrolls away, and a panel paint with slightly round corners so each panel's edge shows. No fonts or borders. With the CSS off, every value and control is still there.

Templates

Three screen shapes cover most tools. Copy the closest one and change it. Each one runs here as it is, against a fake backend in sim.js: replace that one file to connect a real device or server.

TemplateShape and useCSS
1. Station A workbench in the shape of an IDE: top bar, side bar, main, bottom panel, status bar. Each region is a row of tabs over one page. Drag the gaps between them to resize; it fills a window of any size. The example is a test bench: a signal source to start, stop and measure, a chart, a table of captures, a log, and every native control, bound. 24 rules
2. Lab Two columns that wrap. For experiments: set up a training run, queue it, watch the curves, compare runs, inspect one, reuse its config. The setup form is made with the panel() builder. 10 lines
3. Sheet One column, a document. For procedures: a load cell calibration in five steps. Each step unlocks when the one before it passes. The draft survives a reload; the result is a downloadable, printable record. none

The demo is the specimen page: every native control, bound, with a three.js scene. Its experiment panels need the mock server (npm run server), so they stay offline here.

Note: 1-3 are access keys: Alt+key in Chrome, Ctrl+Option+key in Safari.

Library

About 900 lines of TypeScript, built to one ES module. No build step for you.

<label for="gain">gain <output data-text="views.gain"></output></label>
<input id="gain" type="range" min="0" max="1" step="0.01" data-bind="state.gain">
<button data-on="click:actions.save" data-disabled="tasks.save.pending">💾 save</button>

<script type="module">
import { signal, computed, task, bind } from
  'https://cdn.jsdelivr.net/gh/Zaffer/plain-panel@v0.6.0/dist/plain-panel.js';

const state = { gain: signal(0.5) };
const views = { gain: computed(() => state.gain().toFixed(2)) };
const tasks = { save: task(() => fetch('/api/gain', { method: 'POST', body: String(state.gain()) })) };
const actions = { save: () => tasks.save.run() };
bind(document.body, { state, views, tasks, actions });
</script>

Signals, computeds and effects; bind() for the data-* attributes; panel() to build a form from code; task() for requests that show pending and failure; series(), connect() and download() at the edge. The full API is in the README.

For agents

The point of a house style is that every new tool looks and works like the last one, whoever builds it. Give an AI agent this brief:

Build this tool with plain-panel (https://github.com/Zaffer/plain-panel).
Read DESIGN.md first, then README.md. Copy the closest template from
templates/ (station, lab or runsheet). Change sim.js to talk to the real
backend and keep its API. Follow the checklist at the end of DESIGN.md.
